# NoEdit Core 使用规则

一套自包含的 Python 包：直接调用即可产出多页画布（PPT）并导出。
**你写元素 JSON，核心负责落盘、渲染与导出。**

> **核心根目录 = 含 `main.py` 的那一层**（下文记作 `<NECORE>`）。
> 本 skill 自包含分发，`main.py` 与 `noedit_core/` 包就在本 skill 目录里，所以**打包安装后 `<NECORE>` 就是本 skill 目录**；
> 在开发仓库里它是 `noedit_core/` 仓库根（即本 skill 目录的上一级）。所有命令都在 `<NECORE>` 下跑。

## 零号原则（先读这五条，压过其余一切条款）

1. **落笔的就是你自己**。核心不生成内容——元素 JSON 由**你直接写**，再用 `insert` / `update` 落盘。
   没有人替你兜底：配色、版式、坐标、字号、图文对不对，全靠你落笔时写对。
2. **「会动」的效果：HTML 一定动，PPTX 靠内嵌 GIF 也动，其余是静态**。核心**支持**元素动画（`anim`）与微场景（`scene`）：
   导出的 **HTML** 里它们真的会跑（元素动画带「▶ 播放动画」时间轴；微场景是沙箱 `iframe` 在跑你写的 `props.code`）。
   **PPTX** 里微场景会由核心**自动逐帧抓帧并合成 GIF 内嵌**（放映时会动；需本机 Edge/Chrome）。
   **PDF / PNG / SVG 是静态的**——微场景只取 `props.poster` 封面帧，元素动画停在起始帧。
   所以：**要动效就交 HTML（真身）或 PPTX（内嵌 GIF），要投屏 / 印刷就用静态矢量把话说清**；场景代码得你**自己写**（核心不生成代码）。
3. **只走 API，不碰 manifest 文件本身**。改页面 / 元素只走 `noedit_core.api`；直接编辑 `project.manifest.json`
   会绕过规范化与锁，极易写坏工程。
4. **尽量多用矢量，能画则画、能用图标就用图标**。
   （**照片感**的配图可以用你自己带的生图 / 搜图能力，见「图片策略」；但**结构图 / 原理图 / 流程图 / 装置图仍然必须用矢量画**，不许拿生图替代。）
   **矢量优先是本 skill 的第一生产力**——`shape` / `path` / `connector` / `chart` / 图标库做出来的东西
   **视觉效果好、成功率高**，能用矢量的地方**优先用矢量**，别用一大块文字或空白矩形糊过去。
   讲**结构 / 原理 / 机理 / 流程 / 关系 / 装置 / 数据**的页面，
   **必须**用矢量把它画出来——**「能画却不画」按缺陷算**。
   **落笔前对每个节点 / 部件自问一句**「它是不是一个**真实物件或领域标准符号**？」
   （路由器 / 交换机 / 防火墙 / 服务器 / 终端 / 泵阀 / 电阻电容 / 分子 / 细胞 / UML 类框…）；
   **是 → 先 `icon_search` 搜图标库，拿到 `icon_id` 再 `icon_insert`**；
   **库里没有、但画起来不复杂（简单轮廓 / 几何体 / 常规符号）→ 别退回方块，当场用 `path` / `shape` 把它画出来**
   （自绘是常规动作，不是兜底：几笔 `path` 往往比图标库里硬找一个更贴切）；
   确实复杂到画不动，才退回最简形状 + `text` 标注，并在交付说明里点明用了什么替代符号。
   **把具象物件一律画成空白矩形，按「能画却不画」的同类缺陷算。**
5. **调用一律用关键字，看返回一律先看 `ok` / `message`**。
   - **除 `path` 外，参数全写成关键字**（`fps=` / `width=` / `out_dir=` / `name=` …）。核心的公开函数有大量**同类型、带默认值**的位置参数
     （`api.export_scene_gif` 就有 11 个、后 10 个带默认值）：**位置写错不会报错，会把值静默塞进别的字段**——
     文件名收到整段代码、宽度收到帧率，都是这么来的，而且要很久之后才以「文件名很怪 / 结果不对」的样子暴露。
   - **失败的统一样子是 `path` 为空**（`{"ok": false, "path": "", "message": "…"}`）。**`path` 为空是结论不是线索，原因永远在 `message` 里**——
     别从「`path` 空 / 文件名怪」倒推病因，**先读 `message`**。

## 流程红线（每轮开工先默背一遍，压过其余条款）

> 🚩 **完整做 PPT 的流水线，问用户的节点是硬卡点，不许跳过、不许跳过卡点直接收尾：**
>
> **★开工前必问 → 建工程定基调 → 建满页铺底板 → 造母版逐页重铺 → 逐页填内容 → ★收工卡 1（问检查与修正）→ ★收工卡 2（问导出与格式）→ ★交付前查 UI 当前展示的工程并切到待交付工程 → 导出交付（交出 UI 的 web 浏览地址 + 导出文件地址）。**
>
> **「页面都落盘了」不等于收工——必须弹过两张卡、交付前把 UI 切到待交付工程、并把 web 地址交出去。**

### 收工的定义（硬卡点，和流程红线同样严格）

**一轮 PPT 的终点不是「页面都写完了」，是「两张卡都弹过了 + 交付前 UI 已切到待交付工程 + 两个地址都交出去了」：**

1. **全部页元素写完**后，用 `AskUserQuestion` 弹卡问：「要不要我自动做一遍检查与修正？」
   —— 用**卡片**问，不是正文里写一句。
2. **不管上一步选是还是否**，都必须再弹一张卡问：「要不要导出、要哪些格式？」
   —— 选项必须含「**不导出（工程文件就够）**」。
3. **交付前（★ 必做，最容易被漏）：先查 UI 里当前展示的工程，把它切成「要交付的那个工程」**——
   UI 停在上一个工程时，用户点开地址看到的就不是你交付的那份，等于没交付。用什么 API：
   - **查**：`GET /api/ui/current` → `result.project`；为空、或不是待交付工程，就往下切。
   - **切**：`POST /api/ui/open`，体 `{"path":"<待交付工程目录>"}`（运行中直接切，不用重启）。
   - **服务没起**：先 `python <NECORE>/main.py serve --project <待交付工程路径>`（后台常驻）。
4. **收尾回复里必须交出两个地址**：① **UI 的 web 浏览地址**（本机 **`http://127.0.0.1:8760/`**，起法见「浏览器 UI」一节）
   —— **这是必给项，一条都不能少！！！**；② **导出文件的地址**（写**绝对路径**）。`export()` 没跑（用户选了「不导出」）就
   **只给 UI 地址、跳过文件地址**，**不要编一个不存在的导出路径**。

> **选「否」只跳过检查那一步，照样要弹导出卡。** 没弹满两张、**交付前没把 UI 切到待交付工程**、或收尾没交出该给的地址，**禁止说「完成 / 做好了 / 已交付」**，本轮按**未完成**算。

## 开工前：必须先问用户的（★ 卡点 1）

**动手写任何东西之前**，按下面的判据决定「问不问」。凡是问，都用 `AskUserQuestion` **弹卡**，不要在正文里问一句就自己往下做。

### 什么必须先问

**① 作用对象没说死**（只说做什么、没说做在哪）：

- 只给了一个产物描述：「给我做一个 XX 图」「做个公司介绍 PPT」「帮我画个流程图」「做份简历」；
- 或当前语境里同时存在多个工程，你分不清该落在哪个。

→ **问**，选项固定三档：

1. **新建工程**（推荐——用户多半就是要一份新东西）；
2. **打开已有工程**（让用户指名是哪一个）；
3. **在当前工程里做**（写进已打开的那个工程 / 当前页）。

**② 页型清单拿不准**（要不要目录页 / 章节页 / 其他页型）：一次问清（见「步骤 1」）。

**③ 篇幅（页数）没说**：结合材料估一版，让用户确认，别自己闷头定。

**④ 动效档位没说**（要不要微场景、放几个）：和「目录页 / 章节页」一起问清——见「阶段 1」与「微场景」节。用户没选或说「你看着办」→ **按「省着用（2 个）」起步**。

### 作用对象明确 → 直接做，不许问

- 点名了工程：「在我叫 XXX 的工程里」「打开 XXX 那个项目」「XX 项目第 3 页」；
- 点名了页面：「当前页 / 这一页」「第 2 页」；
- 点名了新建（**硬规则，最高优先**）：「新开一个 PPT / 创建一个 / 做一个新的 / 重新做一个」→ **必须** `create_project` 新建工程，再在新工程里做；
  - **「已经有一个差不多的」不是复用理由**——哪怕已存在同名或同题材工程，也**照样新建**，不许拿旧工程充数；「重新创建一个」= 明确要一份**新的**。
  - 这一条**不适用**「不明确就先问」：说「创建一个 PPT」就是明确指令，直接建，不要反问「建在哪」。

### 红线（用户回答前一律不许越）

- ❌ 不许擅自 `create_project` 新建工程；
- ❌ 不许擅自打开 / 续用某个旧工程（**沿用 ≠ 明确**，只有用户点名才算明确）；
- ❌ 不许先往任何页写元素，再回头问「做在哪」。

### 单步指令：只做那一步，做完即停

用户限定了范围（如「只把这张图设为背景」）→ **只做这一步就停**：
导入素材 + 设页面背景，然后**停**。不许再建页、不许填内容、不许顺手导出，也不许把「要不要顺便铺正文」当选项抛给用户。

> ⚠️ 这条只针对「用户把范围限死在某一步」。用户走的是**完整做 PPT 流程**时，★ 卡点**照样必须问**——漏问就是失职。

## 完整做 PPT 流程（阶段 0–8，★ 是必问用户的节点）

```
阶段 0  侦察 + 材料就绪
阶段 1  ★问用户：作用对象 / 页型清单 / 篇幅 / 动效档位 ← ★卡点
阶段 2  定基调（6 色 token）+ 建工程
阶段 3  建满页 + 铺底板与统一装饰
阶段 4  造母版页 → 逐页重铺
阶段 5  逐页填内容
阶段 5▸ 微场景：先 install_scene_lib 缓存库 → 落 scene 元素 + 写 props.code → 补 props.poster（按动效档位卡住数量）
阶段 6  ★问用户：要不要自动做一遍检查与修正         ← ★卡点
阶段 7  ★问用户：要不要导出、要哪些格式（含「不导出」）← ★卡点
阶段 8  ★交付前：查 UI 当前展示的工程（GET /api/ui/current）→ 切到待交付工程（POST /api/ui/open）
        导出并交付：必给 UI 的 web 浏览地址（http://127.0.0.1:8760/）+ 导出文件地址
```

### 阶段 0 · 侦察 + 材料就绪

先把**内容材料**搜集齐：数据、原文段落、术语、引用、图片清单、参考。
材料没齐不许开工——中途补资料 = 返工。缺图按「图片策略」处理：**你自带生图 / 搜图能力就先补上**（要落进 `assets/`），不能就留图槽位。
同时确认「做在哪」（不明确就进阶段 1 问用户）。

### 阶段 1 · ★ 问用户：作用对象 / 页型清单 / 篇幅 / 动效档位

**开工第二步不是配色，是判断「这份题材需要哪些页」。**
默认套「封面 → 目录 → 章节 → 内容 → 致谢」是最常见的错误——**目录页、章节页都是可选页型**。

按三个维度判断：

| 维度 | 影响 |
| --- | --- |
| 篇幅 | ≤ 8 页基本不需要目录页、章节页；≥ 12 页且并列主题多，目录页才开始有价值 |
| 叙事结构 | 线性论证 / 单议题 / 发布会式叙事：靠直接切页推进，不需要章节页 |
| 场合 | 现场讲可省目录；**要发给别人自己看（无人讲解）时目录页反而必要** |

- **目录页**：通常要（页数 ≥ 12 且并列主题 ≥ 3 / 正式汇报提案培训）；通常不要（≤ 8 页 / 单议题 / 发布会叙事）。
  要做就 ≤ 6 行条目，每行「序号 + 标题 + 右对齐页码 + 底部细线」。
- **章节页**：通常要（≥ 15 页且分了 3 个以上大板块 / 发布会大报告）；通常不要（≤ 8 页 / 线性推进 / 每 2–3 页就切一次显得空）。
  要做就超大章节号（低对比同色系，只做氛围）+ 标题 + 一句描述 + 强调线。

**拿不准就问，别猜。** 一次问清：

- 「这份 PPT 需要目录页吗？」——需要 / 不需要 / 你看着办
- 「需要章节分隔页吗？」——需要 / 不需要，一路平铺讲完
- 「除封面、正文、结尾外还要哪些页型？」（多选）——目录 / 章节过渡 / 数据页 / 时间线 / 竞品对比 / 团队介绍 / 问答金句
- 篇幅（页数）：没说就估一版让用户确认
- 「这份 PPT 要加动态效果吗？希望到什么程度？」——一点别用 / 省着用 / 一般用 / 可以用 / 放心用（**动效档位**，决定微场景放几个；五档表见「微场景」节）。**没选就按「省着用」起步。**

判断（或问）完先落一张**页型清单**，它才是后面施工的依据：

```
页 1    封面      产品名 + 一句主张
页 2    章节过渡  声学技术          ← 只有清单里出现时才做
页 3–5  内容页    技术点，每页一个主题
…
页 N    致谢      署名 + 结尾主张
```

**清单里没有的页型不许自己顺手补**（用户没要目录页，就别自作主张加一页）。

**动效档位**（微场景数量上限）是**公共约束**，同样在这步定死；逐页施工时按它卡住微场景个数。

### 阶段 2 · 定基调 + 建工程

「定基调」= 把 **6 个色 token** 定死并写下来（此后**全篇只用这几个色**）：

| token | 用途 |
| --- | --- |
| `bg` | 页面底色 |
| `ink` | 主文字 |
| `accent` | 强调色（一页只用在**一处**） |
| `muted` | 次要文字 |
| `line` | 分隔线 / 描边 |
| `card` | 卡片底 |

配色直接抄 [design-recipes.md](references/design-recipes.md) 第 4 节的六套配方，不要现调。
同时定死**字号阶梯**与**栅格**（见 [page-templates.md](references/page-templates.md) 第 0 节）。

再 `create_project`（`type=ppt`、画布 `ppt-16:9`）；**新工程自带 1 页空白页 = 你的第 1 页**。

### 阶段 3 · 建满页 + 铺底板与统一装饰

> ⚠️ **新工程已经自带第 1 页**（`create_project` 落盘时就有一页空白页，默认名「第 1 页」）。
> **这一页算数，不能当成「还没有页」而忽略**：要 N 页，只需再 `add_page` **N−1** 次。
> 例：一共要 5 页 → 只建 `5 - 1 = 4` 页；照「5 页」建 5 次就多出一页空白页。
> 拿不准就先 `list_pages` 数一下现有页数，**不要凭「我要几页」直接开建**。

1. **先把页数建满**（`add_page` 依次追加）。`all_pages=True` **只作用于调用时已存在的页**，所以必须**先建页、再铺底板**。
2. **底板 + 全篇统一装饰**（页背景色 / 页眉细线 / 页脚署名 / 页码 / 角落装饰）用**一条 `insert(...)` 一个元素、`all_pages=True`** 逐个铺满，或写个循环。这一层是「看起来是一套设计」的最大来源，只花一次成本。
3. 页面背景用图 / 底板色 → 走 `update_page(..., all_pages=True)`（属页面结构），**不要**拿满幅 `image` 元素当背景。

```python
# 建满页 → 铺底板（举例：页背景 + 页脚，全篇统一）
# total_pages = 最终总页数（含 create_project 自带的第 1 页），所以要补的是 total_pages - 1
for i in range(total_pages - 1):
    api.add_page(path)
api.insert(path, {"type": "shape", "name": "底板-底色", "x": 0, "y": 0, "w": 1280, "h": 720,
                  "props": {"shape": "rect"},
                  "style": {"background": "#F6F3ED", "borderWidth": 0}}, all_pages=True)
api.insert(path, {"type": "text", "name": "底板-页脚", "x": 64, "y": 672, "w": 520, "h": 26,
                  "props": {"text": "季度汇报 / 2026"},
                  "style": {"fontSize": 12, "color": "#6E7A70"}}, all_pages=True)
```

### 阶段 4 · 造母版页 → 逐页重铺（关键提速点）

**先把一页内容页/封面/章节页的元素 JSON 定稿**（母版），再对每一页 `insert` 同一份元素、只改文字。
**核心没有「复制页」API**，所以母版元素要在每一页各自重新插入（写个函数循环即可），铺完再逐页 `update` 改文字。

```python
def build_content_page(page_index, title, bullets):
    api.insert(path, {"type": "text", "name": "页标题", "x": 64, "y": 52, "w": 760, "h": 50,
                      "props": {"text": title},
                      "style": {"fontSize": 34, "fontWeight": "700", "color": "#2F3E36"}},
               page_index=page_index)
    # …同页其余元素同样页序插入…
```

不同版式（封面 / 章节 / 致谢）各做一页母版，再按页型逐页重铺。

### 阶段 5 · 逐页填内容

**每页把该页的材料写进元素 props**；内容可以编但要**自洽**（标题 / 正文 / 图注 / 图表标签互相对应）。
数据不确定时加限定语（「公开口径的区间估计」「示意」）并在页脚注明口径。

- **一页的所有元素攒成一批**，不要改一处看一眼（每次写操作都持锁落盘 + 重写 `index.html`）。
- 元素 `name` 用可读中文（`卡片3-图注` / `封面-主标题` / `图槽-01`），后面用 `match.nameContains` 能一把定位同类元素做统一修改。
- 全篇公共约束（色 token / 栅格 / 命名 / 字号阶梯）统一；**逐页设计自己拿捏**。
- **要动效就落 `scene` 微场景**（按阶段 1 定的动效档位卡数量）：先 `install_scene_lib` 缓存库 → 逐页落 `scene` 元素 + 写 `props.code`（必须实现 `seek(t)`）→ **逐个补 `props.poster` 封面帧**。做法与坑见「微场景」节。

### 阶段 6 · ★ 问用户：要不要自动做一遍检查与修正

**全部页元素写完后、动手检查前，先用 `AskUserQuestion` 弹卡问用户**：
「要不要我自动做一遍检查与修正？」

- 用户选**是** → 按下面顺序检查 → 有问题就攒批修正（见下）→ 修正收尾后**进阶段 7**。
- 用户选**否** → **只跳过「检查与修正」这一步**，**直接进阶段 7 去问导出**。

> ⚠️ **选否 ≠ 不导出，选否 ≠ 直接停。** 无论选是还是否，最后都**必须**走到「问导出」那一步。

**怎么做检查**（本核心没有截图 / validate 工具，靠这两条）：

1. **导出 PNG 逐页核对**：`api.export(path, "png", dpi=150)`，看整体节奏、对齐、有没有被底板压住、暗底有没有浅字。
2. **按字数估宽**（[page-templates.md](references/page-templates.md) 第 8 节）：中文按「字号 × 字数」估宽，超了就按
   **减字 → 降字号一档 → 加宽 → 增大 `h`** 的顺序改。
3. 用 `api.list_elements(path, page_index=i)` 看有没有**空白页 / 漏页**。

**发现问题攒成一批 `update` 改掉**——不要一处一调（每次写操作都持锁落盘，改一处看一眼最费时）。

### 阶段 7 · ★ 问用户：要不要导出、要哪些格式

**这是流程最后一个必问节点。** 只要「所有页元素已写完」，**不管阶段 6 用户选没选检查**，都要用 `AskUserQuestion` **弹卡**问：

- 「需要导出吗？」—— **不导出（工程文件就够）** / 需要；
- 「要哪些格式？」（多选）—— PPTX / PDF / HTML / PNG / SVG。

> 有微场景（`scene`）元素时，导出卡里顺带说清：**PPTX 会自动把微场景抓帧成 GIF 内嵌（会动，需本机 Edge/Chrome）**；
> PNG / SVG / PDF 是静态帧。想单独拿 GIF 文件，用 `api.export_scene_gif(path, match=...)`。

> ⛔ **不许只在正文里写一句「要不要导出」就把这轮结束掉**——那等于没问。`AskUserQuestion` 卡片没弹出来就等于没问。**漏问导出 = 整轮流程没走完。**

用户点了哪几种就**只导哪几种**；说不用导出就只给工程路径与 UI 地址。**不许不问、也不许几种都导一遍塞给用户。**

### 阶段 8 · 导出并交付

**① 先把 UI 切到待交付工程（★ 必做，最容易被漏的一步）**

交付前必须确认「用户点开 web 地址看到的就是你要交付的这份工程」：

1. **查当前展示的工程**：`GET /api/ui/current`
   → `{"ok":true,"result":{"project":"<绝对路径>"|null,"name":...,"type":...,"port":8760,"url":...}}`。
   `result.project` 为空、或不是待交付工程 → 下一步切过去。
2. **切到待交付工程**：`POST /api/ui/open`，体 `{"path":"<待交付工程目录>"}`（运行中直接切，无需重启）。
   > 也可用 `POST /api/call` + `{"method":"open_project","args":["<待交付工程目录>"]}` 达到同样效果。
3. **服务没在跑**：先起服务（**后台常驻，别阻塞自己**）：
   `python <NECORE>/main.py serve --project <待交付工程路径>` → 地址 **`http://127.0.0.1:8760/`**。

**② 导出**：按用户点名的格式导出（**只导点名的那几种**）。

**③ 收尾回复里明确写出两样东西**：

1. **UI 的 web 浏览地址** —— **必给项！！！**：**`http://127.0.0.1:8760/`**（见「浏览器 UI」一节）。
   没给这个地址 = 本轮没交付完。
2. **导出文件的地址** —— 写**绝对路径**（默认落在工程内 `export/`；`api.export(...)` 返回的 `path` 就是它）。

> 用户选了「**不导出（工程文件就够）**」时，**只给 UI 地址，不写导出文件地址**——没导出就不给不存在的路径。
> **「UI 已切到待交付工程」+「web 地址给出」缺一不可**，才算交付完；细节见「导出」一节。

## 最小工作流

```
建工程 → 把页建满 → 铺底板 → 逐页 insert 元素 → 需要时 update / delete / reorder → 导素材 → 导出
```

> **「把页建满」要扣掉自带的那一页**：`create_project` 已经建好第 1 页，一共要 N 页就只需再 `add_page` **N−1** 次。

对应核心动作，全部是同步 Python 调用，出错抛 `noedit_core.api.CoreError`（`str(exc)` 可直接展示给用户）。

### 三种使用方式

**A. 命令行**（适合一次性动作，输出 JSON 到 stdout）：

```bash
python <NECORE>/main.py create "季度汇报" --dir D:\work
python <NECORE>/main.py insert D:\work\季度汇报 --json "{\"type\":\"text\",\"props\":{\"text\":\"标题\"}}"
python <NECORE>/main.py export D:\work\季度汇报 --fmt pptx
```

**B. Python 内嵌**（做完整 PPT 优先用这个，一次进程内跑完整批动作）：

```python
import sys; sys.path.insert(0, r"<NECORE>")
from noedit_core import api

p = api.create_project("季度汇报", r"D:\work")
path = p["path"]

api.insert(path, {"type": "text", "x": 80, "y": 60, "w": 900, "h": 80,
                  "props": {"text": "2025 季度回顾"},
                  "style": {"fontSize": 40, "fontWeight": "700"}}, page_index=0)
api.add_page(path, name="数据页")
api.insert(path, {"type": "chart", "x": 600, "y": 180, "w": 560, "h": 360,
                  "props": {"kind": "bar", "title": "营收",
                            "rows": [["Q1", 120], ["Q2", 180]]}}, page_index=1)
# 图标：先搜 id，再插成可编辑的 path 元素（多色则插成 group）
hit = api.icon_search("云服务器", limit=1)["icons"][0]
api.icon_insert(path, hit["id"], x=120, y=140, size=110, color="#2f6fed", page_index=1)
print(api.export(path, "pptx"))
```

> 连续做多页时**优先用 B**：每个 CLI 子命令都是独立进程，反复起进程很慢。把整批动作写进一个脚本一次跑完。

**C. 浏览器 UI**（给人手动预览 / 微调）：

```bash
python <NECORE>/main.py serve --project D:\work\季度汇报   # 打开 http://127.0.0.1:8760/
```

起本地服务后，在浏览器里可预览、点选元素改属性、增删元素 / 页面、导入素材、导出。
UI 的后端就是 `noedit_core.api`（HTTP JSON-RPC），数据落在同一份 `project.manifest.json`，
与 A / B 完全互通——agent 用脚本铺好内容，再把地址交给用户手动微调即可。
**收尾交付时这个地址是必给项之一**（见「收工的定义」第 4 条 / 阶段 8）。
交付前还要**先查 UI 当前展示的工程并切到待交付工程**（`GET /api/ui/current` 查、`POST /api/ui/open` 切，见「收工的定义」第 3 条 / 阶段 8）。

**本地 UI 服务的 HTTP 接口**（服务发现 / 工程设置 / 让界面切到指定工程）。

服务只监听回环、单进程单工程；接口分两类：`GET` 轻量端点 + `POST /api/call` 方法调用。

1. **服务发现**：读 `data/ui.json`（`serve` 启动时写入 `{app, version, host, port, url, pid, project, startedAt}`，正常退出时删除）。
   ⚠️ 该文件可能是上次被强杀留下的——拿到端口后**必须先调接口确认真在跑**。
2. **存活探测**：`GET /api/ping` → `{"ok":true,"app":"..."}`。
3. **当前工程（轻量）**：`GET /api/ui/current`
   → `{"ok":true,"result":{"project":"<绝对路径>"|null,"name":...,"type":...,"port":8760,"url":...}}`
   （`project` 为 `null` = UI 没打开任何工程）
4. **切换当前工程**：`POST /api/ui/open`，JSON 体 `{"path":"<工程目录>"}`（也接受 `?path=<工程目录>`）；
   不是合法工程会明确报错。**运行中直接切，不用重启服务**。
   浏览器页面每 2 秒自检一次当前工程，会**自动跟随切换**（用户无需手动刷新）。
5. **通用调用口**：`POST /api/call`，体 `{"method":"<方法名>","args":[...]}`（`args` 用数组；非数组会被当作单个参数包装）
   → `{"ok":true,"result":...}` 或 `{"ok":false,"message":"..."}`。
   下面这组方法由 UI 服务**自己**处理（不是 `noedit_core.api` 的函数），专管「工程设置 / 工程切换 / 目录浏览」：

   | method | args | 作用 |
   | --- | --- | --- |
   | `ping` | — | 同 `/api/ping` |
   | `state` | — | 当前工程完整视图（画布 + 逐页全字段元素 + 素材 + 地址前缀）；未打开工程 → `{"project": null}` |
   | `create_project` | `name, parent_dir[, preset, ptype]` | 新建工程并**切换**过去（返回同 `state`） |
   | `open_project` | `path` | 打开并切换到该工程（返回同 `state`） |
   | `close_project` | — | 关闭当前工程，UI 回落地页 → `{"project": null}` |
   | `get_settings` | — | `{"defaultDir":"...","custom":true/false}`——`custom=false` = 没设过，用的是默认工程根 |
   | `set_default_dir` | `path` | 设「默认目录」（新建工程的父目录 / 目录树起点 / 导出落点），落盘 `data/settings.json`；目录不存在报错 |
   | `browse_roots` | — | 目录树根节点 `{roots:[{name,path}], defaultDir}`（Windows 列盘符，需 Python 3.12+） |
   | `browse_dir` | `path`（空 = 默认目录） | 列一层子目录并标出哪些是工程：`{path,parent,root,isProject,projectName,entries:[{name,path,isProject,projectName,type,pages}]}` |
   | `upload_asset` | `name, data_url` | 浏览器上传素材（dataURL 字节）写进当前工程 `assets/` → `{asset: {...}}` |

   其余 method（`list_pages` / `add_page` / `insert` / `update` / `export` / `icon_*` 等）**直接转发到 `noedit_core.api`**，
   把工程 `path` 作为第一个参数传进去（详见 [references/api.md](references/api.md)「本地 UI 服务」节）。
6. **画布预览页**：`GET /canvas?page=<0 起>` 用导出同款渲染器渲染当前工程某页（所见即所得，点选元素会 postMessage 回父窗口）。

| `update(path, props, element_id="", match=None, ...)` | 改元素 | `props` 的键是**点号路径** |
| `delete(path, element_id="", match=None, ...)` | 删元素 | |
| `reorder(path, element_id="", match=None, index=-1, to_front=False, to_back=False, ...)` | 调层级 | `index` 越大越靠上 |

| `element_types()` | 列元素类型 + `modelNote` | |

### 元素定位：`element_id` 或 `match`

- `element_id`：`insert` 后从 `list_elements` 的返回里拿 `id`，最准。
- `match`：按描述定位，支持 4 个键 —— `type`、`name`（精确）、`nameContains`、`srcContains`（匹配图片 `props.src`）。
  例：`api.delete(path, match={"type": "shape"}, page_index=0)`。
- **`match` 不给页范围会跨整页匹配**，务必同时传 `page_index`（或 `page_indexes` / `all_pages`）。
- 找不到目标会抛 `CoreError`，不要吞掉。

### 改元素：`props` 用点号路径

```python
api.update(path, {"x": 100, "props.text": "新标题", "style.fontSize": 32}, element_id=tid)
```

- 顶层字段直接写键名（`x` / `y` / `w` / `h` / `z` / `name` …）。
- 进 `props` / `style` 内部用点号：`props.text`、`style.fontSize`、`style.background`。
- **整批修改攒成一次 `update`**，不要一处一调。

### 跨页铺底：`all_pages` / `page_indexes`

`insert` 支持把同一个元素铺到多页：

```python
api.insert(path, {"type": "shape", "x": 0, "y": 0, "w": 1280, "h": 6,
                  "props": {"shape": "rect"}, "style": {"background": "#1f2937"},
                  "name": "底板-页眉"}, all_pages=True)
```

> ⚠️ `all_pages=True` **只作用于调用时已存在的页**。要全篇铺底板，**先把页数建满，再铺**。

## 工程内本地素材（重点：怎么用）

素材的唯一存在形式是**复制进工程文件夹 `assets/` 的本地副本**（没有全局素材库，也没有模板）。

### 用法三步

```python
# 1. 导入（把外部文件复制进 <工程>/assets/，返回登记记录）
rec = api.import_asset(path, [r"D:\pics\logo.png", r"D:\pics\架构图.svg"])["imported"][0]
#    rec = {"id":..., "name":"logo.png", "relPath":"assets/logo.png",
#           "kind":"image", "size":1234, "addedAt":..., "origin":"D:\\pics\\logo.png"}

# 2. 元素引用它——props.src 就写返回的 relPath（相对路径，不是绝对路径）
api.insert(path, {"type": "image", "x": 80, "y": 80, "w": 320, "h": 120,
                  "props": {"src": rec["relPath"], "fit": "cover"}}, page_index=0)

# 3. 查看（确认文件还在）
api.list_assets(path)   # -> [{name, relPath, kind, size, exists}, ...]
```

### 硬规则

1. **只写相对路径 `relPath`（形如 `assets/logo.png`）**，绝不写绝对路径——绝对路径换台机器就失效。
2. **素材随工程文件夹走**。整个工程目录拷到别处，`assets/` 一起搬过去就还能用；这是它和「全局素材库」的本质区别。
3. **别手动往 `assets/` 里丢文件指望被登记**。`assets` 记录由 `import_asset` 写入；手工复制的文件不会被 `list_assets` 看到。反过来，`assets` 记录里文件已丢失的，会在下次落盘时被自动剔除。
4. **文件名冲突会自动改名**（`logo.png` → `logo_1.png`），以返回的 `relPath` 为准。
5. **页面背景用图**：把 `relPath` 交给 `add_page(..., background=...)` 或 `update_page(..., all_pages=True)`。**不要**拿满幅 `image` 元素当背景（会盖住内容、每页各存一份）。
6. **素材一律先落进 `assets/` 再引用**（`props.src` 只认 `relPath`，外部 URL 会导致导出件离线断图）。缺素材就留「图槽位」：一个浅色 `shape:rect` + 一个 `text` 图注，将来换图只改 `props.src`。**你自带生图 / 搜图能力的话可以直接用**——但同样要先 `import_asset` / `upload_asset` 落进 `assets/`，见「图片策略」第 2 档。

## 设计经验（做完整 PPT 必读）

### 6 个色 token 贯穿全篇

一页只用这 6 个 token；**强调色一页只出现一处**；配色 60-30-10（60% 底色 / 30% 次色 / 10% 强调）。
色阶（同色深浅）做装饰圆、页码、水印，比默认灰高级。六套即抄即用的配方见
[design-recipes.md](references/design-recipes.md) 第 4 节。

### 版式规范（CRAP）

- **对比**：字号跨 2 档以上，深浅色差拉大，禁止「大一点点的字」。
- **重复**：同款元素反复用（每张卡都是「强调条 + 编号 + 标题 + 正文」）。
- **对齐**：先定栅格，所有元素只落在列 x 上（三列 `x = 64 / 456 / 848`，列宽 368，间距 24）。
- **亲密性**：卡内间距 8–12，卡间 24，区块间 40+。
- 中文一行 18–26 字；正文 ≥ 14px；行高 正文 1.7–1.8 / 标题 1.25–1.35；**不要两端对齐**；标题层级 ≤ 2。

### 页型判断：目录页 / 章节页是**可选**的

见「阶段 1」。**别默认套「封面→目录→章节→内容→致谢」**。要做目录页就 ≤ 6 行（序号 + 标题 + 右对齐页码 + 底部细线）；
要做章节页就超大章节号（低对比同色系，只做氛围）+ 标题 + 一句描述 + 强调线。

### 卡片堆砌禁令（硬要求）

**「卡片堆砌」是最丑、最像模板的死法**——一页 2×3 卡片网格、下一页又是卡片网格，连摆几页必然难看。

- **一页最多一组卡片**；其余内容一律换版式（时间轴 / 流程箱 / 大数字 + 图表 / 分栏对照 / 五栏编辑式 / 引文大字 / 留白 + 强调线）。
- **同一套 PPT 里禁止连续两页都用卡片网格**。
- **能用留白和标题层级说清的内容，不要用卡片去框**。卡片是最后手段，不是默认版式。

### 表现多元化：不许只有「卡片 + 文字」

做每一页内容页前先问一句「这页的信息最适合哪种形态」，**主动挑一种非卡片的形态**：

| 信息类型 | 优先用的形态 |
| --- | --- |
| 有先后 / 步骤 | 流程图、时间线、阶梯、甘特条 |
| 有层级 / 从属 | 层级图、组织架构图、金字塔、洋葱圈、思维导图 |
| 有循环 / 闭环 | 循环图、环形箭头 |
| 要比较 / 占比 / 趋势 | 统计图（柱 / 条 / 折线 / 面积 / 饼 / 环 / 玫瑰 / 雷达 / 散点…）、象限图、分栏对照 |
| 讲原理 / 机理 | **矢量绘制原理图**（`shape` / `path` / `connector`）、架构图、拓扑图、装置示意 |
| 要强调一个数 | 大数字 + 单位 + 一句话，配细线或色块 |
| 要装饰 / 点缀 | 矢量图标（`icon_search` + `icon_insert`）、矢量符号 / 标志（`shape` 预设 / `path`）、色带、角标 |
| 要「活」/ 要动 | **微场景（`scene`）**——氛围动画 / 会动的流程图·图表 / 主题小场景（数量按动效档位卡住，见「微场景」节） |

**硬要求**：

1. **一套 PPT 走遍多种形态**，不许连续两页同一种版式。
2. **能上统计图 / 流程图 / 时间线 / 层级图 / 循环图 / 原理图的，就不要退回「卡片 + 文字」**。
3. **凡是能画原理图的地方，一律不许只写文字或卡片**——讲**结构 / 原理 / 机理 / 流程 / 关系 / 装置 / 数据**的页面，**必须**用矢量把它画出来；**「能画却不画」按缺陷算**。
4. 静态示意一律优先用矢量原语（`shape` / `path` / `connector` / `chart`）画——进 PPTX 还是可编辑真矢量，改色改位只动一个字段。
5. **具象物件要画成具象图形**（真实设备 / 器件 / 分子 / 细胞 / 标准符号）：先 `icon_search` 找图标插入，图标库没有再看 `shape` 预设能否表达，不够就 `path` 自绘，或 `import_asset` 导入图标图片；**把具象物件画成空白矩形 = 缺陷**。
6. 矢量是默认态：**全篇 ≥ 60% 的页面应含矢量元素**，纯文字页 ≤ 30%，数据 / 原理页 100% 矢量，每 3–5 页一个「全矢量重页」。
7. **要「动」的部分才交给微场景（`scene`）**，个数按用户选的**动效档位**卡住（见「微场景」节）；静态部分仍用矢量画，**两者不冲突**——档位高就多上会动的演示图，档位低就全靠矢量静态图撑住表现力。

> 具体怎么画：**「哪里用矢量、用哪种、用多少、怎么高级」** → [vector-playbook.md](references/vector-playbook.md)；
> **科研图表 / 原理图 / 机制图的硬规范** → [sci-vector-drawing.md](references/sci-vector-drawing.md)；
> **具体领域画什么结构**（架构 / 流程 / 结构 / 通路 / 波形 / 拓扑，14 母题 + 领域图种库）→ [diagram-atlas.md](references/diagram-atlas.md)；
> **示意图构成 / 流程图 / 架构图的做法** → [design-recipes.md](references/design-recipes.md) 第 9–10 节。

### 微场景（scene）：唯一的动效引擎

**`scene` 元素是这套系统里唯一能「动」的载体**（元素 `anim` 只是入场动画，不是内容动画）。它就是一段跑在沙箱 `iframe` 里的前端代码——**核心不生成代码，`props.code` 得你自己写**。产出的东西分三类，**三类都要主动想到**：

- **氛围动画**——光带流动、粒子漂浮、裂纹蔓延、星野绕行、余晖呼吸……给版面加韵味，补上静态排版做不出的那层「活气」。
- **演示动画**——把本来要静态画的示意图换成会动的版本：节点流转、圈层扩散、时间轴推进、数据爬升。即「**会动的流程图 / 图表**」，讲逻辑比一张静态示意图清楚得多。
- **主题小场景 / 卡通形象**——做个会动的小角色或小意象。小猫小狗可以，但**更好的做法是直接呼应题材**：讲美苏冷战就做「蘑菇云从地面升起、顶部翻涌发光」「两人隔桌掰手腕、桌面微颤」「铁幕缓缓落下」「火箭点火升空」。**判据是「一眼能读懂」**——扫一眼就知道这页在讲什么，比一条抽象光带更抓人。

**所以施工时别只盯封面和章节页**：逐页过一遍「哪里静态会显得空、发闷」和「哪块示意图换成动的更好讲」，把答案都落成微场景。**成本最低、收益最高的位置是边缘长条、角落小景、标题下的局部强调条**——一条 1280×100 的流动光带就能让整页活过来，比再加一张卡片划算。

#### 开工先问：动效档位（微场景数量上限）

**动手前必须先用 `AskUserQuestion` 弹卡问用户**（和「要不要目录页 / 章节页」一起问）：

> 「这份 PPT 要加动态效果吗？希望到什么程度？」——一点别用 / 省着用 / 一般用 / 可以用 / 放心用

| 档位 | 微场景数量上限 | 静态图怎么配 |
| --- | --- | --- |
| 一点别用 | **0 个** | 原理图 / 效果图 / 装饰图**全部**用矢量工具（`shape` / `path` / `connector` / `chart`）画静态图 |
| 省着用 | **2 个** | 静态图**优先**用矢量工具画；微场景只放在最值当的一两处 |
| 一般用 | **3–4 个** | 微场景与矢量静态图**掺着来**，不要全用微场景 |
| 可以用 | **5–6 个** | 微场景与矢量静态图**掺着来**，不要全用微场景 |
| 放心用 | **6–10 个** | **自主规划**——按内容需要铺氛围动画 / 演示动画 / 主题小场景 |

- 数量是**硬上限**，任何一档都不许超；用户没选或说「你看着办」→ 按 **省着用（2 个）** 起步。
- **静态图与微场景是两回事**：不论哪一档，「不用会明显变差」的静态图（原理图 / 架构图 / 流程图 / 数据图）**本来就该用矢量原语画**——档位只决定「动的部分」放几个，不决定静态图要不要做。
- 除满幅氛围页外，**一页最多一个微场景**，别让两处动画抢注意力。

#### 形态自由，不要只做成正方形

| 用法 | 尺寸 | 说明 |
| --- | --- | --- |
| 满幅氛围 | 1280 × 720 | 封面 / 致谢，配一层压暗渐变叠大字标题 |
| 边缘长条 | 1280 × 100 ~ 160（页眉/页脚），或 80 × 720（左/右竖条） | **动态装饰条**：流动光带、扫描线、粒子带。成本极低但整页立刻「活」起来 |
| 侧栏竖幅 | 600 × 720，靠页面一侧 | 章节页主体图形（如产业链、圈层） |
| 主题小场景 / 卡通形象 | 一般 200 × 240 ~ 600 × 400 | **会动的小角色或小意象**：优先做直接呼应题材的；放角落或侧栏装点界面、掩盖空白，比塞一个色块高级得多 |
| 原理演示 | 按内容给尺寸 | 节点流转、圈层扩散、时间轴推进——即「会动的流程图」，替代表格 / 静态示意 |
| 局部强调 | 任意长条 | 标题下划线的流光、数字背景的波纹 |

用法可以自己探索；关键是把「静态会显得空」的位置交给它。

#### 写 `props.code`（生成质量几乎全取决于这一段）

代码跑在独立沙箱 `iframe` 里（拿不到主页面 DOM、CSS 不外泄、崩了只影响这个容器），用生命周期驱动：`mount(container, params)` 建场、`seek(t)` 定格到第 `t` 秒、`unmount()` 收尾。

```json
{"type": "scene", "x": 0, "y": 620, "w": 1280, "h": 100,
 "props": {"duration": 6, "loop": true, "libs": [], "poster": "data:image/png;base64,...",
           "code": "window.mount=function(c){/* 建 canvas，按 c.clientWidth/Height 定尺寸 */};\nwindow.seek=function(t){/* 按 t（0..duration 秒）画出一帧 */};\nwindow.unmount=function(){/* 停 RAF、清资源 */};"}}
```

**硬规范（漏一条就出问题）**：

1. **必须实现 `seek(t)`**——这是 PPTX 抓帧成 GIF 的前提。只自播、不实现 `seek` 的场景，核心抓不出时间点，GIF 判定失败、退回 `poster`。把「第 t 秒该画成什么样」写成纯函数，RAF 自播也走同一个 `seek`。
2. **顶层出现 `return` 是语法错误**，整段脚本直接不执行——`return` 只能待在函数体内。
3. **画布尺寸自适应**：`mount` 里按 `container.clientWidth / clientHeight` 定尺寸，别写死像素（同一个场景可能被摆成不同尺寸）。
4. **画面里不要出现文字 / 字母 / 数字 / 图标 / 外部图片**——微场景是纯几何动效（要文字就用旁边的 `text` 元素叠上去）；**第三方库只走 `props.libs` 白名单**，别在 `code` 里手写 `<script src=…>` 引外部资源（加载失败 + 抓帧报错）。
5. **要压大标题的场景**，在对应区域**留出低对比的暗区**，别让动效压到正文上。
6. **配色只用你已定的 6 色 token**，与全篇一致，别冒出体系外的颜色。
7. **要画角色 / 意象就写具体**：「一朵蘑菇云从画布底部升起、顶部缓慢翻涌发光」远好过「做一个跟主题相关的动画」。**含糊描述必然换来含糊结果**。
8. **用前端库先缓存**：`props.libs` 里写 `p5` / `anime` / `gsap` / `three` / `chart` / `d3` / `matter` / `confetti` 之前，先 `api.install_scene_lib("gsap")`（留空 = 全部，**会联网**），再用 `api.scene_libs()` 确认 `cached`。**未缓存时场景不跑并提示「缺少本地库」。**
9. **同名多处出现的场景要逐个补**（如页眉流光条在 9 页各有一份）：用 `match` 取元素时是「所有匹配项」，别以为是字典只留最后一个——**要逐个改就改用 `element_id` 精确处理**。
10. **攒批落盘**：poster 是「逐场景 × 逐出现位置」的批量活，先把所有结果算完，最后**一条**写请求铺到所有匹配元素上；别生成一张、写一次、再看一眼。

#### 封面帧（poster）必须备，否则静态交付是空的

**这是最容易漏、后果最明显的一条。**

- 事实：**PDF / PNG / SVG 里微场景不跑**，只画 `props.poster`；**没有 poster 就只剩深色占位框**（PPTX 里也会先闪一下占位框）。
- 补法：把这份 `code` 挂起来、跑到一个有代表性的 `t`（通常取动画中段）定格，截图转成 `data:image/png;base64,…` 写进 `props.poster`；也可先用 `api.export_scene_gif(...)` 抓出帧，再取其中一帧转 dataURL。
- 会盖住底层装饰的封面 / 侧栏场景，**保留透明通道**（别转 JPEG，否则会糊出一块矩形盖掉底图）。
- 大尺寸 poster 可先缩到 0.7 再编码，体积降一半、肉眼无差。
- 只想单拿一份 GIF 文件：`api.export_scene_gif(path, match={"name": "…"})`。

#### 交付话术

- **HTML**（`export(path,"html")`）：微场景是**真身**，`iframe` 里在跑。
- **PPTX**：核心导出前用本机 Edge/Chrome **逐帧抓帧合成 GIF 内嵌**，放映时会动；**前提是容器实现了 `seek(t)`**（没实现就退回 `poster`）。
- **PDF / PNG / SVG**：静态，微场景只取 `poster`。
- 所以：**要动效就交 HTML（真身）或 PPTX（内嵌 GIF）；投屏 / 印刷用静态矢量把话说清。**

#### GIF 抓帧失败：先按 `message` 分流，别急着改 `code`

`api.export_scene_gif(...)` 失败一律返回 `{"ok": false, "path": "", "message": "…"}`——**原因只在 `message` 里**。照它分流，改错方向会白干一整轮：

| `message` 里出现 | 真实病因 | 怎么办 |
| --- | --- | --- |
| `未找到 Microsoft Edge 或 Chrome` | 本机既没浏览器也没 playwright | 装浏览器（或 `pip install playwright`）；**不是代码问题** |
| `抓帧失败：无头浏览器没有截出可用画面` | 抓帧通路整个没出图（**环境 / 时序**） | 先确认浏览器可用、重试；**与 `code` 无关，别改 `code`** |
| `逐帧抓到的画面完全相同` | 容器没随 `seek(t)` 重画 | 才轮到查 `code`（见下面第 1 条） |
| `缺少本地库：…` | `props.libs` 里的库没缓存 | 先 `api.install_scene_lib(...)` 再重试 |
| `至少需要 2 帧` / `帧数据都解不出来` / `帧数据太大` | 帧数或体积越界 | 调小 `fps` / `width` |

**两条硬提醒：**

1. **`mount` / `seek` 里抛的异常会被核心静默吞掉**（不报错，只表现为「画面没变」或「一片空白」）。所以「画面完全相同」时，**先在 `seek` 顶部插一句自证**（画个随 `t` 变化的标记）确认 `seek` 真被调到、且没在开头就抛错，**再**去怀疑写法。**禁止**一遇到抓帧失败就把整套 `code` 推倒重写。
2. **没装 playwright 时，抓帧靠反复冷启动浏览器**（单场景十几次，批量 4 个场景就是几十次）。**「部分场景失败」在这种模式下是常态**——先确认走的是哪条通路（`python -c "import playwright"`），别把环境抖动当成代码缺陷。

### 界面装饰与点缀（矢量图形怎么用）

**总原则**：装饰一律用**矢量原语**（`shape` / `path` / `connector`）静态摆出来，改色改位置只动一个字段。

| 位置 / 场景 | 用什么 |
| --- | --- |
| 页眉 | 顶部细线 / 渐变色条 / 小三角 / 一段圆弧（线用 `shape:"line"` 或小 `h` 的 rect，**显式写 `borderWidth`**） |
| 页脚 | 页码底衬小色块、细分割线、角落小色标（命名 `页码` / `装饰-页脚`） |
| 角落 | 直角三角、同心圆 / 光环、点阵、网格（`shape` 预设 + `group` 成组，**低透明度、不压正文**） |
| 封面 | 满幅色块 / 对角斜带 / 大圆 / 细线框（只留一个视觉重点，其余留白） |
| 章节过渡 | 一侧竖色带、超大编号、半透明大字母 / 大圆（一种形状语汇重复即节奏） |
| 目录 / 内容 | 左侧色条、卡片底、序号圆点（卡片底用圆角矩形，默认无边框） |
| 时间线 / 流程 / 架构 | 圆点节点 + 连线 + 箭头 + 层级底色块（连线用 `connector`，必须显式写宽度） |
| 象限 / 矩阵 | 十字轴线、四象限浅底、区域标注（轴线显式写宽度；底色用 `style.background` + 透明度） |
| 对比 / 对照 | 两栏色块、中缝分隔线、对称角标（两栏同尺寸镜像） |
| 数据 / 图表页 | 图表浅底圆角矩形、强调色高亮条、引线标注、图例小色块 |
| 收尾 / 致谢 / 金句 | 一线一点、渐隐色块、单一强调色圆（极简，靠留白） |

**硬规则**：

1. 装饰**不抢正文**：低饱和 / 低透明度，正文区留白优先；一页只有一个视觉重点。
2. 命名统一：`装饰-*` / `底板-*` / `页码`，便于一次性批量改。
3. 全篇统一的装饰**用 `all_pages=True` 一次铺满**，不要逐页重画。
4. 叠加顺序：**底板先插 → 装饰次之 → 内容最后**（z 递增，后插在上）。
5. 只靠描边的形状 / 连线**必须显式写 `borderWidth`**（默认 0 → 不可见）；形状填充只认 `style.background`。
6. 装饰若用了**渐变 / 元素级不透明度（`opacity` / `fillOpacity`）/ 阴影 / 弧线 `path`**，PPTX 里会回退成截图——装饰无伤大雅，但别让**正文元素**也沾这些效果。（`style.background` / `borderColor` 里 `rgba(...)` 自带 alpha 会原生写成 `a:alpha`，不算回退。）

### 图片策略

**核心约束（不许破）**：`props.src` 只能写**工程内 `assets/` 的相对路径**（如 `assets/xxx.jpg`）。
**不许写 http(s) 外链**——导出件要**离线自包含**，外链一断图就没了，工程也失去「拷走就能用」的性质。

配图按来源分四档，**有哪档用哪档**：

1. **用户提供了本地图** → `api.import_asset(path, [文件...])` 导进工程 `assets/`，元素
   `{"type":"image","props":{"src":rec["relPath"],"fit":"cover"}}`。导入前检查水印、截图边框、奇怪留白。
2. **你（agent）自带生图 / 搜图能力** → **可以用，不排斥**。拿到图后**必须先落进工程再引用**：
   - 拿到**文件路径** → `api.import_asset(path, [该文件])`；
   - 拿到 **dataURL 字节** → 走 UI 通道 `upload_asset`（`POST /api/call`，
     `{"name":"xx.png","data_url":"data:image/png;base64,…"}`），它会写进当前工程 `assets/` 并登记；
   - 再用返回的 `relPath` 写 `props.src`。
   **只用来做「照片感」的东西**：实景、人物、风景、材质、氛围、封面视觉。
   **不要**拿它画结构图 / 原理图 / 流程图 / 装置图 / 数据图——那些按零号原则第 4 条**继续用矢量**
   （AI 生图做这类图结构必错，还常带乱码文字）。
   **别让生图写文字**（中文 / 数字几乎必错）：要文字就用 `text` 元素叠上去。
   **风格必须贴全篇 6 色 token**，别让配图成为体系外的颜色。
   搜图注意版权：对外交付 / 商用优先用生图或用户自备的图。
3. **没有图、也没能力搞图** → 留「图槽位」：`shape/rect` + 主题浅色底，命名 `图槽-01`，
   配图注双行（14px 标题 / 12–13px 说明）。将来替换只改 `props.src` 与 `fit`。
4. **完全不用图** → 纯几何装饰：色块、细线、圆、渐变、编号。比找图快得多。

**图片要当整页底板 / 全篇背景** → 设**页面背景**（`update_page(..., all_pages=True)`），不要逐页插满幅 `image` 元素。

## 导出

```python
api.export(path, "html")     # 自包含静态 HTML（可交互预览的真相）
api.export(path, "pptx")     # PPTX（矢量优先，可继续编辑）
api.export(path, "pdf")
api.export(path, "png", pages="1,3", dpi=300, transparent=True)
api.export(path, "svg", pages="")
```

- 默认落到**工程内的 `export/` 目录**；`out_dir=` 可改。
- 返回统一含 `{"ok", "path", "message", "format"}`；`png` / `svg` 还带 `paths`（多页）与 `warnings`。
- 依赖：**pptx 需 python-pptx**；**pdf / png / svg 需本机有 Edge 或 Chrome**（无头打印/渲染）。缺依赖时 `ok=False` 并在 `message` 里说明。
- `png` / `svg` 支持 `pages`（`"1"` / `"1,3"` / `"2-5"`，空 = 全部）、`dpi`（96/150/300/600）、`transparent`。
- **导出前无需额外保存**：所有 `insert/update/delete` 都已即时写盘并刷新 `index.html`，导出读的就是最新状态。
- 交付前先把 UI 切到待交付工程（`GET /api/ui/current` 查、`POST /api/ui/open` 切），交付时**必给 UI 的 web 浏览地址**（`http://127.0.0.1:8760/`，**漏了按未交付算**）+ **导出文件绝对路径**；说明**矢量保真看 SVG / PDF**。没导出就只给 UI 地址。
- 细节与返回结构见 [references/export.md](references/export.md)。

## 硬事实（别踩的坑）

- 画布 `ppt-16:9` = **1280 × 720 px**，原点在**左上角**；元素可超出画布（出血/装饰），导出按画布裁剪。
- `insert` 的 z 自动 = 当前页最大 z + 1，**后插的在上面** → **底板先插、内容后插**。若发现被底板压住，把底板 `z` 设为 0。
- `shape` / `path` **默认无边框**，填充只认 `style.background`（写 `style.fill` 无效，会被并回 `background`）；**只靠描边的图形**（`shape:"line"` / `path` 线稿 / `connector`）**必须显式写 `style.borderWidth`**，否则不可见。
- 渐变只能靠 `props.fillType: "gradient"`，**不要**往 `style.background` 塞 `linear-gradient()`。
- `lineHeight` 只写**倍数**（如 `1.4`），写 `38` 这类像素值会异常放大崩版。
- **`table` / `chart` 的文字颜色必须与「衬底」做反差，不是与「页面底」**：深色底（含黑底）必须显式给浅色 `style.color` + 浅色 `headerColor` + 浅色图表文字色（`titleColor` / `labelColor` / `valueColor` / `gridColor` / `axisColor`）；白底只能用深色系；表格自带衬底（`headerBg` / `altBg` / `rowBg` / `highlights`）时，文字跟那块衬底做反差。表身单元格默认不写色、继承 `style.color`。
- 表格**默认不透明白底**（`rowBg:#ffffff`）——放暗色页会自带一块白底。
- 同一工程的写操作**串行**（有跨进程文件锁）；只读接口可以并发。**先写、再读**（写完再查，别放同一批）。
- 所有坐标单位都是画布 px；页面索引从 0 开始，`-1` 表示「所有页 / 不指定」。
- `locked:true` 的元素语义是「这块已定稿」，但**核心不做强制拦截**——`update` / `delete` 照样改。所以**避开锁定是自己的纪律**：动手前先看 `locked`（`list_elements(..., full=True)` 能看到），批量修改先筛掉它们。用户说「这页我自己摆好了 / 别动这块」时，同样把该页现有元素当锁定对待：**只补它缺的，不重排、不改已有**。

## 能力边界（这些做不了，别浪费力气）

| 你想要 | 本核心怎么办 |
| --- | --- |
| 让 AI 自动生成页面内容 | 没有生成能力——**你自己写元素 JSON** |
| 在导出件里带动效 | HTML 一定动；**PPTX 里微场景由核心自动抓帧合成 GIF 内嵌**（会动）；PDF / PNG / SVG 静态（微场景取 `props.poster` 封面帧，元素 `anim` 停起始帧） |
| 单独要一份微场景 GIF 文件 | `api.export_scene_gif(path, match={"name": "..."})`——核心用本机 Edge/Chrome 逐帧 `seek(t)` 抓帧再合成（容器必须实现 `seek(t)`） |
| 自动生成微场景代码 / 封面帧 | 没有——`props.code` 得**你自己写**，封面帧 `poster` 也得自己备 |
| 微场景要用前端库 | 先 `api.install_scene_lib("gsap")`（或留空下全部，**这一步会联网**）；`api.scene_libs()` 看哪些已缓存。未缓存时场景不跑并提示「缺少本地库」 |
| 全局素材库、模板 | 没有；素材用工程内 `assets/`（见上节），版式自己按 `element_types()` 搭。**你自己带的生图 / 搜图能力不受此限**（见「图片策略」第 2 档）——但图必须先落进 `assets/` |
| 想把具象图标放进页面 | **有内置矢量图标库**（1800+ 个）：`api.icon_search("箭头")` 找 id → `api.icon_insert(path, id, x=, y=, size=120, color="#c0392b")`。单色图标插成一个可编辑 `path`（能换色）；多色图标插成 `group` 容器 + 分层成员。整组浏览用 `api.icon_groups()` / `api.icon_list(group)` |
| 截图 / 视觉复核 | 导出 `png` 后自行查看 |
| 编辑器里的布尔运算 / 科研波形预设 | 没有；自写 `props.d` |

> 一句话：**静态图（图形 + 图标 + 文字 + 连线 + 图表）全都能做；要「动」就用 HTML（真身）或 PPTX（核心自动内嵌 GIF）——PDF / PNG / SVG 是静态帧**；自动生成内容 / 场景代码 / 封面帧，这里没有。

## 反面清单（出现任一条就说明你做错了）

**流程相关：**

- ❌ **该问不问**：作用对象没说清就直接开工；页型清单拿不准却自己猜；篇幅没说却自己定；**动效档位没问就自己开动效**（没问→按「省着用 2 个」起步）。
- ❌ **跳过收工卡**：页面写完直接说「完成了」——没弹「检查与修正」卡、没弹「导出」卡。
- ❌ **交付前不切 UI**：没查 `GET /api/ui/current`、没用 `POST /api/ui/open` 把 UI 切到待交付工程——用户点开地址看到的不是你要交付的那份。
- ❌ **收尾不给 web 地址**：只说「完成了」却不给 **`http://127.0.0.1:8760/`**——**这是必给项，漏了按未交付算**。
- ❌ **只喊不弹卡**：在正文里写一句「要不要导出」就当问过了——`AskUserQuestion` 卡片没弹出来 = 没问。
- ❌ 把「选否」理解成「直接停」——选否只是跳过检查，**照样要问导出**。
- ❌ **擅自扩范围**：用户只让做一步（如「只把这张图设为背景」），却顺手建页 / 填内容 / 导出。
- ❌ **自作主张补页型**：页型清单里没有的页型，顺手加一页。

**操作相关：**

- ❌ **逐元素往返**：改一处调一次 `update`，改一处看一眼——该攒成一批。
- ❌ 无视 `locked:true` 的元素，批量修改时不筛掉。
- ❌ 直接改 `project.manifest.json`、或写脚本改盘（绕过 API = 破坏一致性）。
- ❌ 做「不做也不影响交付」的操作，或「收效甚微但极费时间」的操作。
- ❌ 把大段元素 JSON / 大图 / 全量 `list_elements` 结果反复拉进上下文（该压成结论）。
- ❌ 拿绝对路径写 `props.src`；或手动往 `assets/` 丢文件指望被登记。
- ❌ **把外部 URL 写进 `props.src`**（导出件离线打开就断图）。**生图 / 搜图本身不禁止**——但图必须先 `import_asset` / `upload_asset` 落进 `assets/`，再写 `relPath`。
- ❌ 缺图不留图槽位：既不导入、也不生图，却留一片空白。
- ❌ 拿生图去画结构图 / 原理图 / 流程图 / 数据图（该用矢量；AI 生图做这类图结构必错、还带乱码文字）。
- ❌ **位置参数调用**：`path` 之外还按位置排实参——错位不报错，会静默把值串到别的字段（`name` 收到整段代码、`width` 收到帧率）。**除 `path` 外一律写关键字**。
- ❌ **看 `path` 判失败原因**：导出 / 写接口失败时 `path` 恒为空，那是结论不是线索，**原因在 `message` 里**。

**微场景（scene）相关：**

- ❌ **没问动效档位就自己铺微场景**，或**超档位**（选了「省着用」却放了 5 个）。
- ❌ `props.code` **没实现 `seek(t)`** → PPTX 抓不成 GIF，退回静态帧。
- ❌ `props.code` 顶层写了 `return` → 整段脚本直接不执行。
- ❌ **漏补 `props.poster`** → PDF / PNG / SVG 里只剩深色占位框。
- ❌ 用了没缓存的 `props.libs`（漏了 `install_scene_lib`）→ 场景不跑，提示「缺少本地库」。
- ❌ 在 `code` 里手写 `<script src=…>` 引外部资源，或在画面里画文字 / 数字（该用 `text` 元素叠）。
- ❌ 一页里塞两处微场景抢注意力（一页最多一个）。
- ❌ **抓帧失败就推倒重写 `code`**：先按 `message` 分流——「抓帧失败」多半是环境 / 时序（浏览器没出图、反复冷启动），**跟 `code` 无关**。
- ❌ **查「画面完全相同」时跳过自证**：`mount` / `seek` 的异常会被核心静默吞掉，**先在 `seek` 里插一句随 `t` 变化的标记**确认它真被调到，再怀疑写法。
